Signaling UX - practical-first wizard

A comparison mockup. The normal path asks what the railroad must do, then produces familiar signaling. Prototype fidelity and unusual display technology remain possible without becoming prerequisites.

What this version is testing

Can a modeler build useful signaling without knowing a prototype rulebook, naming the signaling discipline, or drawing a track plan? JMRI data tests the advanced path's ceiling; it does not set the vocabulary of the recommended path.

Ask what the railroad must do first. Offer familiar signaling by default. Ask which prototype to reproduce only when the user chooses prototype fidelity.

Original ordering

  1. Choose signaling system and role
  2. Choose speed or route discipline
  3. Choose signal style
  4. Bind topology and wire lamps
→

Practical-first ordering

  1. Say how this piece of track is used
  2. Accept practical signaling or opt into fidelity
  3. Choose a compatible appearance
  4. Name only the local blocks and masts involved

Questions for comparison

  1. Can a modeler answer the Track use choices without signaling expertise?
  2. Does Practical sound complete rather than second-rate?
  3. Is choosing appearance after fidelity late enough to prevent impossible combinations?
  4. Does Next mast per route feel understandable without a track diagram?
  5. Are placeholders preferable to requiring geographical creation order?
  6. Should APB sections and interlockings be visible objects or generated implementation detail?
  7. When should Bowties expose the terms ABS, APB, interlocking, and CTC?
  8. Is the Custom branch visible enough to make unusual signaling feel supported?
