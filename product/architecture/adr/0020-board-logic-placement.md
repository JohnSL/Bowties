# ADR-0020: Board Logic placement

**Status**: Accepted
**Date**: 2026-11-24
**Related**: [ADR-0012](0012-all-layout-edits-draft-layer.md) (2026-11-24 extension), [ADR-0015](0015-backend-layout-state-single-owner.md)

## Context

A Signal LCC has 32 `Logic` conditionals. A group is a run of consecutive
Logic slots: every member but the last has Function `Group`, and the last
has `Last (Single)`. Bench testing (Spec 020, recorded in
`product/hardware/signal-lcc/conditionals.md`) showed the rule covers the
whole board: an earlier group with an undefined Function value (raw 3)
silenced a later, valid group. Nothing on the board refers to a Logic slot
by number: variables come from events or a Track Circuit number, and actions
send events. Masts are different: a mast's set-aspect events and Link
Address are generated by the board for that mast, and other boards and JMRI
consume them.

Until Spec 020 E3a, the compiler picked the lowest free Logic slot for each
facility, and the facility recorded the slot ("never a re-pick"). An
internal signal (E3) needs a two-slot group, so the slot after a signal's
Logic may be taken. Making room means moving Logic, and a move must keep the
board-wide rule.

## Decision

- **Content apart from placement.** The compiler
  (`bowties-core/src/signaling/compiler.rs`) describes each signal's Logic
  rungs relative to its group. One pure per-board planner,
  `bowties-core/src/signaling/logic_placement.rs` (`plan_logic_placement`),
  decides which slots each Bowties group occupies.
- **The planner owns the board-wide rule.** Groups already placed stay put.
  A new group takes the lowest free run of the length it needs. From E3, when
  a group must grow, the fewest slots move, the signal's own group first, in
  a write order that never leaves a `Group` without its terminator. Logic
  Bowties does not own with a Function value the CDI does not define, or a
  `Group` run with no `Last (Single)`, blocks placement on that board, and
  the issue names the Logic. A fix is only a named release the modeler
  confirms (ADR-0012 2026-11-23 rule); the planner never repairs on its own.
- **Placement is a board fact, recorded per board.** The facilities document
  holds `logicPlacement`: for each board, groups keyed by facility ID,
  signal ID, first Logic and length. It changes through one whole-board
  replace delta, `SetLogicPlacement`, so Done, Discard, Save and reopen keep
  it in step with the facilities (ADR-0012). Moving one facility's group
  never edits another facility's record.
- **Masts and Track Circuits never move.** Each signal records its own
  `resources` (board, mast, Track Circuits). Moving a mast changes the
  events others consume; moving a circuit would rewrite the Logic that
  reads it.

## Considered Options

- **Facilities hold handles into a Logic manager.** Rejected: a handle is a
  second identity beside the signal ID (allocation, orphan cleanup), and a
  handle table leaves the board-wide rule split across each facility's
  compile.
- **Derive ownership from the board's content** (the run whose actions send
  this signal's mast events), with no placement record. Rejected: a hand
  edit silently disowns a group and Bowties places a second one driving the
  same mast.
- **Anchored growth, refuse when the next slot is taken.** Rejected: it
  refuses while enough free slots exist elsewhere on the board.

## Consequences

- A facility record alone no longer lists every slot it uses; consumers
  that need the full set (removal, the Remove dialog, Review) combine the
  signal `resources` with the board's placement
  (`slots::facility_claimed_slots`).
- Facilities schema "2.0" exists only on the Spec 020 branch, so the record
  changed in place without a migration.

## 2026-11-24 extension: groups change length (Spec 020 E3)

- A facility's recorded group whose demanded length changes is resized by
  `plan_logic_placement`: it grows in place when the following Logic is free,
  otherwise only that facility's own group moves to the lowest free run (its
  old slots count as free); a shrink keeps the first slot. Another facility's
  group is never moved. No run that fits is `NoFreeLogic` for the signal.
- `PlannedLogic.vacated` lists the Logic the facility held before and no
  longer holds; the compiler releases them after the new group's edits.
- A Track Circuit is free when no facility claims it and no Logic Bowties
  does not own uses it as a Source; a release empties Remote Mast Description
  and gives the Link Address a fresh event ID.

## 2026-11-24 extension: facilities across boards (Spec 020 E5)

- A facility's signals may be on different Signal LCC boards. The compiler
  picks each signal's mast and Track Circuit on that signal's own board, and
  calls `plan_logic_placement` once per board; the compile result lists one
  `NodeLogicPlacement` per affected board.
- A receiver's Track Circuit takes the next signal's mast Link Address from
  the next signal's board. When that board's Link Address has not been read,
  `LinkAddressMissing` names the next signal and the board.
- Vacated Logic and released Track Circuits are reset on the board that held
  them; a resize on one board writes nothing to another.

## Invariants

- Every Logic slot Bowties writes for a facility comes from
  `plan_logic_placement`; no other code picks a Logic slot.
- A placed group is a run of consecutive Logic slots; every member but the
  last is written `Group` and the last `Last (Single)`.
- The planner places nothing on a board whose Logic Bowties does not own has
  an undefined Function value or an unterminated `Group` run.
- `logicPlacement` never names a facility that does not exist
  (`DeleteFacility` prunes its groups).
- Masts and Track Circuits recorded in a signal's `resources` are never
  re-picked.
